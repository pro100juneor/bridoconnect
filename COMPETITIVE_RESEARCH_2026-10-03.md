# BridoConnect — конкурентный ресёрч и план внедрения (2026-10-03)

**Источник:** 5 параллельных исследовательских проходов (тематическое насыщение по отзывам
App Store / Google Play / Trustpilot / Reddit / BBB / CFPB / PissedConsumer / профильным форумам)
по ~50 приложениям 5 категорий:

1. Creator-monetization/membership — Patreon, Ko-fi, Buy Me a Coffee, Substack, Gumroad, Boosty, OnlyFans, Fansly, Fanhouse, Fanfix, Fourthwall, Memberful, Liberapay.
2. Crowdfunding/donations — GoFundMe, Kickstarter, Indiegogo, Donorbox, JustGiving, Chuffed, Fundly, Liberapay, GlobalGiving.
3. Live streaming + tipping — Twitch, Kick, TikTok Live, Bigo Live, YouTube Live, Trovo, Streamlabs/StreamElements, Facebook Stars.
4. Marketplace/escrow/payments — Fiverr, Upwork, Freelancer.com, Escrow.com, PayPal, Wise, Venmo, Revolut, Payoneer, Cash App.
5. Onboarding/trust/chat/notifications/a11y/localization — Patreon, Fiverr, Upwork, Twitch, Discord, Telegram, WhatsApp, Bumble, Tinder, Airbnb, Depop, Vinted.

**Честность о методе:** это тематическое насыщение (темы читались до прекращения повторения
across источников), НЕ построчный подсчёт 5000 отзывов. Количественные рейтинги (Trustpilot и т.п.)
— вторичные, на дату чтения; перед цитированием в маркетинге перепроверять.

---

## ГЛАВНЫЙ ВЫВОД (совпал во всех 5 проходах)

**Во всей категории сломано доверие к деньгам.** Топ-боль пользователей — одинаковая везде:
заморозка всего баланса/аккаунта без объяснения, непрозрачные комиссии и скрытый FX-маркап,
молчащая бот-поддержка именно в момент денежной проблемы, двойные/тройные списания, скам с уводом
сделки «мимо платформы». Для эскроу-маркетплейса Brido это не «фичи», а **ядро дифференциации**:
прозрачность эскроу + предсказуемость выплат/правил + быстрая человеческая поддержка по деньгам.

Второй по силе драйвер дохода (из praise): **прямой монетизируемый контакт** — платные DM и
чаевые в лайве с реакцией стримера в реальном времени (у Brido уже есть чаты и стримы — дёшево
монетизировать). Третий — **recurring/подписочная** поддержка поверх разовых сделок.

## ПРИОРИТИЗИРОВАННЫЙ БЭКЛОГ

Теги исполнимости (рамка владельца «Всё, кроме визуала» + отсутствие Deno/sandbox локально):

- **[SAFE-NOW]** — невизуально, верифицируется локально (tsc/eslint/build/БД) → внедряю автономно.
- **[D-003]** — money-path (edge-функции/рейлы): без Deno/sandbox не верифицируется → владельцу на sandbox.
- **[VISUAL]** — трогает вид/вёрстку/новые экраны → готовлю и показываю на «ok».
- **[OWNER]** — решение/текст/политика владельца.
- **[DATA-MODEL]** — требует серверной модели данных (крупнее, отдельный спек).

### A. Доверие к деньгам (highest impact)

1. **Заморозка только оспариваемой суммы сделки, не всего кошелька.** Спор блокирует лишь сумму
   конкретной сделки; остальной баланс доступен к выводу. [D-003 + DATA-MODEL]
2. **Прозрачная разбивка платежа ДО подтверждения:** «спонсор платит X → комиссия Brido Y% →
   процессинг Z → получатель получит W», + FX отдельной строкой со сравнением с mid-market. Это
   прямое лекарство от топ-жалобы (скрытый спред PayPal / «tip» GoFundMe / стекинг комиссий Ko-fi) и
   повтор главной похвалы Wise. [VISUAL] (расчёт — [SAFE-NOW] утилита, показ — [VISUAL])
3. **Любой tip/взнос платформе — OFF по умолчанию (opt-in, без dark-pattern).** Главная
   репутационная ловушка всей crowdfunding-категории (GoFundMe/JustGiving/Fundly). [OWNER + VISUAL]
4. **Явные состояния эскроу в UI + таймер:** Funded → In progress → Submitted → In review →
   Released / Disputed. [VISUAL] (машина состояний — [SAFE-NOW]/[D-003], индикатор — [VISUAL])
5. **Auto-release по молчанию (напр. 14 дней → релиз получателю) с видимым обратным отсчётом.**
   Сильнейшая хвалимая фича Upwork/Escrow.com. [D-003] (RPC + cron) **+ требует явного решения о сроке [OWNER]**
6. **Трекер статуса выплаты (инициировано→обработка→в пути→зачислено) + ETA + причина любого hold.**
   «Как трекинг посылки». [VISUAL] + [D-003] (данные статусов).
7. **Идемпотентность платежей** (Idempotency-Key на Stripe/провайдерах) — защита от двойных списаний
   при сетевых ретраях Capacitor. Топ-жалоба Patreon. [D-003]
8. **statement_descriptor / понятный дескриптор в банковской выписке** (имя кампании/Brido) —
   снижает чарджбеки «не узнал списание». [D-003]
9. **Обёртка сырых ошибок провайдеров в generic + серверный лог** (сейчас `catch` отдаёт клиенту
   `error.message` провайдера — утечка внутренностей). [D-003] (edge; без Deno не верифицирую здесь)
10. **Отдельный риск-резерв под чарджбеки вместо заморозки всего баланса.** [D-003 + DATA-MODEL]
11. **Гарантированный вывод остатка при закрытии/ограничении аккаунта** (анти-Fiverr «ссылка не
    работает»). [D-003]
12. **Выбор, кто платит комиссию** (спонсор/получатель/50-50) на уровне сделки (модель Escrow.com). [VISUAL + D-003]
13. **Публичная простая страница тарифов/лимитов** (анти-Freelancer.com). [OWNER + VISUAL]
14. **Региональный роутинг выплат:** для украинских получателей НЕ полагаться на приём PayPal и вывод
    Payoneer→укр.карта (запрет с 01.2025 по требованиям НБУ); предлагать Wise/IBAN/BTCPay/локальные
    методы по гео. Критично для UA-фокуса. [OWNER + D-003]

### B. Прозрачность расходования и повторные донаты (доказанный эффект на доверие)

15. **Обязательные апдейты получателя с фото/чеками/прогрессом.** Академически: каждое «рабочее»
    слово в апдейте ≈ +доход; сертифицированная кампания ≈ +доход (IU/EurekAlert). [VISUAL + DATA-MODEL]
16. **Авто-квитанция спонсору ≤24ч и thank-you ≤3 дня; апдейт при достижении цели.** [SAFE-NOW (send-email шаблоны)/D-003]
17. **Уведомления спонсорам о проблемах/нарушениях по сделке** (аналог Kickstarter fulfillment-alert). [D-003 + VISUAL]

### C. Доверие/верификация/анти-скам (критично для UA и App Store Guideline 1.2)

18. **Report + Block в один тап из чата и профиля + реакция на жалобу ≤24ч.** Это ОБЯЗАТЕЛЬНОЕ
    требование Apple Guideline 1.2 для UGC/чатов — без него ревью завернут. [VISUAL + SAFE-NOW (бэкенд жалоб)]
19. **Детектор ухода «мимо платформы» в чате** (телефоны/ссылки на внешние мессенджеры/«плати вне
    Brido») с инлайн-предупреждением. Топ-вектор скама Fiverr/Upwork/Telegram. [SAFE-NOW (детектор-утилита) + VISUAL (баннер)]
20. **Постоянный баннер в чате сделки:** «Платите только через escrow Brido — вне платформы защиты нет». [VISUAL]
21. **Selfie/photo-верификация получателей с видимым бейджом** (модель Bumble, анти-catfish). [VISUAL + D-003 (KYC)]
22. **Карточка доверия в шапке чата/профиля:** статус верификации, число завершённых сделок, рейтинг,
    «на платформе с…». [VISUAL + SAFE-NOW (данные)]
23. **Двусторонние отзывы по сделке** (взаимно скрыты до публикации обоих; оставить можно только после
    оплаченной escrow-сделки — модель Airbnb). Частично уже есть (reviews.revealed). [SAFE-NOW/D-003 + VISUAL]
24. **Risk-scoring и лимиты для новых аккаунтов; детект тестовых микротранзакций** (урок Fundly/Stripe-shutdown). [D-003 + DATA-MODEL]

### D. Онбординг и вход (свежо и опасно — вход Apple/Google только что добавлен)

25. **НЕ хранить Apple/Google ID единственным ключом:** стабильный внутренний user_id + резервный
    способ входа; Apple/Google — attached identity. Защита от сбоя типа мая-2025. [D-003 (auth) + DATA-MODEL]
26. **Запоминать последний метод входа и показывать «вы входили через Apple/Google»** — убирает
    дубли-аккаунты и путаницу с Private Relay. [SAFE-NOW (хранение) + VISUAL (показ)]
27. **Верифицировать домен-отправителя для Apple Private Relay** (иначе магик-линки/письма молча
    пропадают) + проверка доставки приветственного письма. [OWNER (DNS) + D-003]
28. **Авто-merge при коллизии email** (один человек вошёл и через Apple, и через email). [D-003]
29. **Прогрессивный онбординг:** смотреть ленту/каталог до регистрации; телефон/KYC — только при
    создании сделки/выводе; у каждого разрешения микротекст «зачем». [VISUAL + D-003]
30. **Prod-мониторинг успешности логина + реальный E2E Apple/Google в проде** (не только TestFlight). [OWNER + D-003]

### E. Чат: надёжность и богатство (драйвер удержания №1)

31. **Оптимистичная отправка со статусами (отправляется/доставлено/ошибка-ретрай) + офлайн-очередь +
    восстановление WebSocket при возврате из фона** (боль Discord именно в Capacitor-lifecycle). [SAFE-NOW (логика) + VISUAL (статус-иконки)]
32. **Read receipts / typing indicators / реакции / голосовые** (most-wanted чата). [VISUAL + DATA-MODEL]
33. **Монетизируемые DM и платные закреплённые сообщения** (Super Chat-аналог, но дешевле по трению,
    через существующий кошелёк, с чётким сплитом). Доказанный топ-доход суперфанов. [VISUAL + D-003]

### F. Стриминг

34. **Прямой тип через кошелёк/эскроу БЕЗ промежуточных «коинов»**; показывать «вы платите Y →
    стример получит X». Снимает главный негатив Bigo/Facebook. [VISUAL + D-003]
35. **Синхронный on-screen алерт о типе с таймкодом стрима** — чтобы стример зачитал имя (главный
    драйвер повторных донатов). [VISUAL + D-003]
36. **Low-latency по умолчанию (~2–4с) с авто-фолбэком на normal при слабой сети UA.** [D-003 (стрим-инфра)]
37. **Адаптивный битрейт + тумблер «Экономия трафика» + авто-реконнект вместо чёрного экрана.** [VISUAL + D-003]
38. **Push-лента открытия в стиле TikTok (тест на малой аудитории по engagement), НЕ сортировка по
    зрителям** — рычаг роста малых креаторов. [DATA-MODEL + VISUAL]
39. **Паник-режим модерации (1 тап: emote-only + заморозка новых чаттеров) + follower-only/slow mode.** [VISUAL + D-003]
40. **Rate-limit и hold на типы от новых/неверифицированных** (anti-raid + anti-chargeback). [D-003]

### G. Уведомления

41. **Гранулярные тумблеры по типам: DM / сделка-escrow / лайв / маркетинг; транзакционные никогда не
    мешать с маркетингом; серверная проверка доставки.** Дефолт — только «любимый в эфире», остальное opt-in. [VISUAL + D-003]

### H. Общее качество (App Store доверие)

42. **Жёсткий QA на краши (Capacitor/iOS) + crash-reporting.** Доверие к финприложению рушится от
    первого краша (урок GoFundMe app). [OWNER (Sentry/ключ) + SAFE-NOW (интеграция обёртки)]
43. **Содержательные empty states с CTA** вместо пустого/случайного экрана. [VISUAL]
44. **a11y-базис:** accessibilityLabel/aria-label на всех иконках-кнопках (НЕ меняет вид), + Dynamic
    Type/контраст WCAG AA (это уже визуал). Также требование Apple для UGC. [SAFE-NOW (labels) + VISUAL (type/контраст)]
45. **Профессиональная локализация с контекстом (UK/RU):** формальный украинский, резерв длины строк,
    корректная плюрализация/рода, человеческая вычитка. [OWNER + SAFE-NOW (i18n-правки)]
46. **Никогда не менять правила вывода/пороги/комиссии задним числом** без заблаговременного
    уведомления (почти бесплатно, большой буст доверия). [OWNER (политика)]
47. **«Trust Center» — как работает эскроу, когда и как вернуть деньги, сроки — простым языком до
    регистрации.** [OWNER (текст) + VISUAL]
