# Известные ограничения и технический долг

Честный список на 13.09.2026. Ничего из этого не скрыто в коде — по каждому пункту
есть комментарий в соответствующем файле или задача.

## Блокирует коммерческий запуск

1. **Stripe в тестовом режиме.** Все платежи (донаты, магазин, промо) идут по
   тестовым ключам. KYC (Stripe Identity) — тоже тестовый: верификации не настоящие.
2. **Supabase на Free-плане.** Нет автоматических бэкапов, нет PITR, проект
   замораживается после ~7 дней неактивности (однажды уже происходило).
3. **Демо-данные на проде.** Аккаунты `buyer@`/`seller@brido.local` (пароль
   `password123`) и три демо-товара видны реальным пользователям. Вычищаются
   перед запуском; пока оставлены намеренно — идёт тестирование.

## Функциональность деградирует без ключей (код готов, ключей нет)

4. **LiveKit** — создание эфира на проде вернёт ошибку (нет LIVEKIT\_\* секретов).
5. **Resend** — email-уведомления no-op (send-email тихо пропускает без ключа).
6. **Sentry** — инициализация есть, DSN не задан: ошибки в проде не собираются.
7. **PayPal / Adyen / Wise / dLocal / BTCPay** — альтернативные платёжные рейлы
   написаны, но не сконфигурированы и не активированы в UI; единственный рабочий
   рейл — Stripe. PayPal delayed-disbursement release помечен TODO в
   `release-escrow/index.ts` (нужны partner-credentials).

## Технический долг / архитектурные упрощения

8. **Unit-тестов нет** (vitest настроен, файлов 0). Покрытие — только e2e Playwright.
9. **route-smoke e2e рассчитан на staging-бэкенд**; локальный edge runtime
   в CLI-стеке не поднят, поэтому функции локально не сервятся.
10. **`supabase/config.toml` отсутствует** — локальный стек работает на дефолтах CLI.
11. **Счётчик непрочитанных в чатах** обновляется при загрузке списка (poll),
    без realtime-пуша на бейдж.
12. **Sign in with Apple не реализован в клиенте** (провайдер в Supabase включён,
    client_id `de.brido.connect`); на iOS соцвход скрыт целиком (требование 4.8
    закрыто скрытием Google-кнопки).
13. **Профили публично читаемы** (`profiles_select using(true)`) — осознанное
    решение для маркетплейса. Платёжные идентификаторы вынесены в закрытую
    таблицу `profile_payment_accounts` (миграция 035, 12.09.2026).
14. **Premium на iOS скрыт** (внешние платежи — guideline 3.1.1), доступен в вебе.
15. **Домен** — vercel.app-поддомен; почта поддержки — gmail. Работает, но
    выглядит некоммерчески.
16. **История git** содержит период, когда `node_modules/` и `dist/` были
    закоммичены (вычищено из индекса 13.09, история не переписывалась).

## Внешний аудит 13.09.2026 — найдено и исправлено в тот же день

Перед передачей пакет прошёл четырёхстороннее ревью (безопасность/RLS, платёжная
логика, клиент, инфраструктура). Критические находки исправлены немедленно
(миграции 036–037 + патчи функций, применено на staging и прод, проверено
живыми эксплойт-тестами):

- **[crit] Сервисные SECURITY DEFINER RPC были вызываемы клиентами** (apply_*_payment,
  release_escrow, increment_raised и др.): накрутка raised, самоназначение спонсором,
  подделка релиза эскроу. → 036: drop legacy-перегрузок + revoke execute (11 функций).
- **[crit] Два пути самоназначения роли admin** (метаданные signup; прямой UPDATE
  profiles) и само-верификация. → 037: whitelist роли в handle_new_user, триггеры
  защиты привилегированных колонок profiles/deals, пересборка политик
  verification_requests.
- **[crit] Refund не отзывал transfer у получателя** (destination charge) — потеря
  денег платформы при сговоре. → reverse_transfer + refund_application_fee +
  атомарный claim рефанда (закрыта и гонка release↔refund).
- **[crit] send-email позволял анонимную рассылку фирменных писем с произвольным
  HTML.** → только авторизованный пользователь и только себе; HTML-экранирование
  переменных шаблонов.
- **[high] Захват чужого эфира** (is_host из тела запроса). → проверка host_id.
- **[high] Wise-payout без проверки оплаты и идемпотентности.** → guard по
  escrow_released_at + одноразовый claim.
- **[high] Двойное зачисление raised при ретраях вебхука.** → дедуп по event.id
  до денежных RPC.
- **[high] Спам в чужие чаты, двойные ордера, обход kill-switch публичных страниц,
  промо-тариф с клиентской длительностью.** → 037 + патч create-checkout.
- **[high] CI был красным** (нет script lint, фиктивный typecheck, vitest exit 1),
  9 реальных ошибок типов. → починены типы, скрипты, workflow.
- **[high] FX-cron прода постил в staging** → курс валют на проде не обновлялся.
  → пере-schedule на прод.
- **[med] Прод-fallback ключей в client.ts, битые SEO-домены (bridoconnect.com),
  мёртвый tailwind-конфиг (все анимации), нет ErrorBoundary.** → исправлено.

### Осталось НЕ исправлено (нужны продуктовые решения)

- **Эскроу на Stripe destination charges условен**: деньги доступны получателю с
  момента оплаты; «release» — бухгалтерская пометка. reverse_transfer возвращает
  средства при рефанде (вплоть до отрицательного баланса connected-аккаунта), но
  честный эскроу требует перехода на separate charges & transfers (transfer в
  момент релиза). Рекомендуется до масштабирования.
- **Кошелёк-«пополнение» — деньги в один конец**: withdrawal/расход баланса не
  реализованы. Либо достроить, либо убрать пополнение из UI.
- **Учёт не double-entry**, баланс считается на клиенте; рефанд задваивается в
  выписке (две строки).
- **Oversell товара при конкурентных оплатах** (stock без резервации), рефанды
  orders не обрабатываются, статусы shipped/completed недостижимы.
- **crypto_addresses в публично читаемых profiles** (подмена адреса/деанон);
  sponsor_reveal и field_visibility энфорсятся только на клиенте.
- **i18n**: смена языка не перерисовывает открытые экраны; EN/DE-режим — ~80% UI
  всё ещё на украинском; валюта сделки фиктивна (всё трактуется как EUR).
- Тумблер 2FA пишет флаг, но 2FA нет; фейковый «онлайн» в чате; корзина не
  очищается после покупки; README устарел; init-database — дрейфнувшая копия
  схемы; VAPID-переменные мертвы.
