## 3. Админские учётки

Остались два профиля с `role='admin'`:

| email                 | имя     | последний вход |
| --------------------- | ------- | -------------- |
| `oleksii@brido.local` | Oleksii | 08.09.2026     |
| `anton@brido.local`   | Антон   | ни разу        |

**Это тоже сидовые учётки, и их нужно заменить перед публичным запуском.**
Причины:

1. Пароль к `oleksii@brido.local` лежит открытым текстом в
   `scripts/seed-local.mjs` — то есть в публичном репозитории на GitHub.
2. Домен `brido.local` не существует, письмо для сброса пароля туда не дойдёт.
   Восстановить доступ штатным путём невозможно.

Правильный порядок замены: владелец регистрируется на сайте настоящим адресом
и задаёт свой пароль сам → его профилю выставляется `role='admin'` →
сидовые админы удаляются. До этого шага их не удаляли намеренно: иначе
админка осталась бы без единого входа.

## 5. Как выполнять запросы к проду

Через Management API (`psql` на машине не установлен):

```bash
TOK=$(security find-generic-password -s "Supabase CLI" -a "supabase" -w \
      | sed 's/^go-keyring-base64://' | base64 -d)
curl -s -A "curl/8.6.0" \
  -X POST "https://api.supabase.com/v1/projects/wtevirwkshidxskqpvtu/database/query" \
  -H "Authorization: Bearer $TOK" -H "Content-Type: application/json" \
  -d '{"query":"select 1"}'
```

Заголовок `-A "curl/8.6.0"` обязателен: Cloudflare отдаёт ошибку 1010 на
user-agent питоновских клиентов.
