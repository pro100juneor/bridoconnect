# BridoConnect — план работ до рабочей демо-версии для питча

**Дата:** 2026-09-20 · **Основа:** `AUDIT_INDEPENDENT_2026-09-20.md`
**Цель:** демо/питч инвесторам, где **всё показанное работает по-настоящему** и **ничего не имитирует успех**.
**Область платежей:** все рельсы (Stripe, PayPal, Wise, dLocal, Adyen) должны реально проводить операции — для питча допустим **sandbox/test-режим** провайдеров, но с настоящим движением средств в песочнице.

## Принципы (не нарушать)

1. **Честность вместо заглушек.** Ни один экран не показывает `completed/выплачено/підключено`, если операция реально не прошла. Пока метод не доделан — он **скрыт из UI**, а не «зелёный».
2. **Демо на sandbox-ключах.** Реальные ключи не коммитим; для питча — тестовые аккаунты провайдеров.
3. **Каждая видимая кнопка работает или её нет.**
4. **Публичные факты — правдивы.** Юрлицо, статистика, инфраструктура — только реальные данные либо явная пометка «приклад/demo».

Приоритеты: **P0** — блокеры демо (ложь/деньги/юр-риск), **P1** — довести рельсы и живые флоу, **P2** — полировка/развитие. Оценка объёма: **S** ≤0.5д, **M** ~1-2д, **L** ~3-5д.

## Дальнейшее развитие (после демо, P2+)

Направления, усиливающие продукт для следующего раунда:

- **Платежи:** вынести общий split/escrow-слой (сейчас логика дублируется по 5 рельсам); единый reconciliation-отчёт по ledger.
- **Комплаенс:** полноценный AML/KYC-поток (ComplyAdvantage prod), аудит-лог операций, экспорт для регулятора.
- **Премиум/монетизация:** реальная модель подписки (2-12), тарифы, промо.
- **Соц-функции:** пуш-уведомления (инфраструктура `push_subscriptions` уже есть), лента/рекомендации, модерация контента.
- **Наблюдаемость:** Sentry/PostHog уже подключаемы по consent — добавить дашборды воронки донатов и алерты на сбои вебхуков.
- **Тесты:** довести покрытие критичных путей до CI-гейта на каждый PR.
